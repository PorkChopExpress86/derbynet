# Briefing an agent on a ticket

A delegate reads `CLAUDE.md` on its own. A brief names the ticket and what is specific to it, and leaves out what this file and `CLAUDE.md` already say.

## Rules for every agent

- Never use the fable model, and never spawn a subagent on it. Use opus for the hardest work.
- Before building, list what `origin/master` already has for the ticket: its commits (`git log origin/master --grep '#N\b'`), its endpoints in `server/legacy_api/registry.py`, and the handlers and services that exist. Build what the list lacks, and put the list in the final report.
- Work in its own git worktree, on a branch named `issue-<n>-<slug>`. Check `git branch --show-current` before any pull or merge in the main clone, because other sessions use it.
- Commit with `git -c user.name=PorkChopExpress86 -c user.email=<owner email> commit`, and end each message with the `Co-Authored-By` line the session gives. Push the branch, and leave the PR and the merge to the lead.
- Edit no issue body and no owner decision. Put proposed ticks in the final report.
- Send the lead each question only the owner can answer as soon as you find it, then build around it. #54 found its token question early and reported it after the whole ballot was built. Each question recommends what PHP does, with its file and line, or says why not: #231 recommended dropping dead class ids to `[]`, which shows every class, though the same message said PHP shows nobody; the owner chose PHP's rule, which cost a second commit, parity run and full suite. Start the parity run and the affected tests (`plan/bin/affected-tests`, owner, 2026-11-11) on the head that answers the questions. `plan/bin/ci-suites N` also lists the parity-gate entries that name the ticket, a question to raise at the start.
- A trade-off you would name in your report as part of what the user sees, such as a page that shows less than the page it stands for or less than PHP shows, is such a question: send it before building on it, even when you judge it fine. #237's thumbnails drew 6 of 15 kiosk pages emptier than the kiosk (no lineup, award, on-deck chart or QR code), which the implementer judged a fair trade-off and built on; the owner chose D84 instead, and the fix took a second round. Code, docs and the PR body cite the lead's answer by the decision it rests on and the ticket (`D10`, `#272`), since a reviewer sees no message from the lead: #272's docstring said "the lead's choice B" until review.
- Send the lead each gap you know of and have no test for before the push, with what you tried, so the lead or review can build the test while the branch is open. #239's implementer named a page that reloads mid-check in its report; review's stand-in page that reloads every second crashed the tool 8 of 8.
- Before building, check each number, range and choice in the ticket's acceptance boxes against the PHP source, and send a mismatch to the lead then. #48's ticket said a fake roster "sees 30" where PHP adds -2 to +2 racers to each group at random (`action.racer.fake.inc:31-35`, C57), and its setting ranges came from the ticket instead of `settings.php`'s inputs; the review found both.
- A behavior the ticket's Risks or the lead's condition states, such as "not on a timer", gets a test like an acceptance box. #250's fit() on every poll passed every test until review.

## Django handlers

- A handler under `server/legacy_api/handlers/` is a thin adapter. It parses `ctx.args`, calls a service, and encodes the result. The guard in `server/legacy_api/tests/test_registry.py` fails a handler that writes through the ORM.
- A service that changes roster, inspection, lane, or result data takes `core.services.lock_race_state(event_id)` first inside `transaction.atomic()`. A handler or a `ui` view never reads race state before a service call and acts on it after: the service reads it again under the lock. A read the change must match, such as #48's snapshot before a purge, is taken under that lock too: taken before it, a racer added in between was purged unrecorded. `server/ui/tests/test_read_then_act.py` flags a view that refuses on what it read, or answers with a row it read and never handed to the service; build the toast and the Undo from what the service returns.
- One user action is one service call, so all its writes commit or roll back together. #42's review found a racer saved in one transaction and its award settings in a second.
- A ported action refuses in PHP's order: one test sets every refusal condition at once and expects PHP's first code. A row it creates sets every column PHP's INSERT sets. #54's `vote.cast` asked for the password before PHP's closed check, and its Voters row left out `when_cast` and `ip_addr`.
- A record that must survive a refusal is written after the atomic block, because the rollback removes it.
- A service that changes a setting decides what happens to each stored row the setting governs, and a test changes the setting with such rows present. When PHP and the owner decisions leave it open, ask through the lead. #70's review found a stored weigh-in pass kept after the partition's maximum changed, and a Failed weigh-in kept after the mode changed.
- Every endpoint needs a `LEAK_REQUESTS` entry in `server/legacy_api/tests/test_event_leak.py`.
- A deliberate difference from PHP goes in the endpoint's `divergences` in the registry, citing a quirk id or an owner decision (`D48`). A difference that a recorded golden fixture shows also goes in `server/tests/golden/deviations.json` (D25).
- Each parity-gate allowance (a `ParityPath` in `PARITY_PATHS` or `STEP_PATHS`, a contact window) gets a test beside it where a difference just outside its decision still fails: another role, another scene, a contact after the window. #218's review found D16 allowed for every caller, D5 for logged-in callers, D10 for every scene, and a window with no end when no later poll came. When the decision relates the two sides, such as D82's "Django keeps at least PHP's rows", one test breaks that relation (PHP 12 against Django 5); a normalizer's fallback branch gets one too (an id that names no row against a renumbered id). #221's review found both passing.
- A new Django-only endpoint is added to `DJANGO_ONLY` in `server/legacy_api/tests/test_registry.py`. A new event-scoped model needs a row in `server/core/tests/populated.py`. `plan/bin/affected-tests` maps a model or a migration to `core/tests`, `legacy_api/tests/test_registry.py` and `legacy_api/tests/test_event_leak.py`, and a handler or a service to the last two, because these fail only there otherwise and CI's full suite finds them a round late (owner, 2026-11-11).
- Replay suites hold PHP's state after each script step: `roster/tests/test_group_scenarios.py`, `legacy_api/tests/test_groups_parity.py`, `racing/tests/test_round_scenarios.py`, `racing/tests/test_finalists.py`. Run them before changing a behavior they cover. A fix they break needs a narrower condition or a recorded deviation, never an edited expectation.

## UI pages

- htmx inheritance is off (`server/ui/templates/ui/base.html`), so each element that makes a request names its own `hx-target`, `hx-swap`, `hx-sync` and `hx-include`. `server/ui/tests/test_htmx.py` checks the page-wide htmx rules.
- A value the page sends back to the server, such as an Undo link's query or a hidden field, is client input. The service checks it as it checks a new request, and the same request sent twice changes nothing the second time. #44's Undo stored a forged `runs=0` and restored a step twice. `hx-sync="...:drop"` drops a request only while another is in flight, so a repeat sent after the reply needs a service-side guard, such as #49's import token. `server/ui/tests/test_undo_links.py` replays and alters each Undo link a view offers; a new Undo adds its scenario there. A list the page keeps and posts back whole, such as #54's chosen cars, gets a test that makes one item invalid between load and post: #54's vote page kept a car the award could no longer take, and every later vote failed.
- A page that differs from the PHP page it replaces cites a quirk id or an owner decision (`D69`) at the difference, in the code and in any README that describes it, as an endpoint's `divergences` do. #49 and #50 each shipped five such differences with no id until review. `server/ui/tests/test_navigation.py` fails a newly built page until its PHP page is in `ROUTE_DIVERGENCES`, `UNDECIDED_DIVERGENCES` (no id yet; the PR's `## Still open` names each) or `LIKE_PHP` (`server/legacy_api/registry.py`). A difference the ticket's scope asks for is a question for the owner through the lead before the PR, not an `UNDECIDED_DIVERGENCES` entry: #54 parked two there that became D77.
- Each rule lives in its service, and a view or a page's `state.py` calls it. `server/ui/tests/test_rules_in_services.py` flags a lane mask or a service limit copied into one, or a literal bound in its template.
- `server/ui/tests/test_query_growth.py` reads each page, poll and hx-get fragment at two sizes of race day and fails when the query count grows; its first test names a fetched URL missing from `URLS`. Its `race_day()` also feeds `test_poll_signatures.py`, so a feature that adds stored state adds rows in that state there, or both checks pass without rendering it. #70's review found race day with no weigh-in. Race day puts a kiosk on every page in `kiosks.services.kiosk_pages()`, so a kiosk page's thumbnail on the dashboard is counted (#237 retro).
- A new page checks its PHP page's `<script src>` tags: `server/ui/tests/test_php_libraries.py` fails a third-party library the port neither serves nor records as replaced. #52's `fullscreen.php` left out `screenfull.min.js`.
- A setting's bounds and choices are PHP's markup: `server/ui/tests/test_settings_bounds.py` reads them from `settings.php` and `coordinator.php`. A new page with number inputs or `<select>` choices gets the same check.
- `server/tools/source-checks.sh` runs the tests that read only the source (PHP cites and claims, `QUIRK_DECISIONS` records, copied helpers, rules in services, read-then-act, the registry) in seconds, and the pre-push hook runs it. Run it after each batch of edits: #48 found five of them failing one round at a time. A new test that reads only the source goes into its list: `server/tests/test_source_checks.py` fails a test module that imports `ast` or calls `rglob` and is neither listed nor exempt. #238's fixture-order failure passed the hook because the guard wasn't listed, and only the full suite found it.
- The page-wide checks fail a new page only once it is registered and renders: `pytest -n auto ui/tests/test_navigation.py ui/tests/test_every_view.py ui/tests/test_query_growth.py ui/tests/test_photo_urls.py` takes about 3 minutes, and `plan/bin/affected-tests` adds them for every template and ui view in the diff (owner, 2026-11-11). Run them as soon as the page has its URL and its registry entry. #52's full suite found four such failures, one round at a time.
- A test for a box that says "X shows what Y shows" compares what each draws: a racer's name, a car number, a label, a value. Checking which template, page name or `data-` attribute X carries proves only that the right template ran. #237's "each of the 15 pages has a thumbnail that matches the page it shows" checked `data-page` and passed while 6 thumbnails were emptier than their kiosks. Review checks this against each such box.
- A browser test reads the page after a click, check or fill through a retrying `expect` (`to_have_css` per card for a CSS order). A one-shot read is kept only where one read is the point, such as "nothing changed", and its comment says so; an experiment showing the read lands late enough is no such reason, and neither is "nothing redraws it", a claim about the page that the Evidence rules cover. #220's sort test kept one-shot reads on that argument and review sent them back; #240's on-deck counts carried `# one read: ... redrawn only when the poll's answer changes`, where `kiosk-ondeck.js:101` redraws at every poll. A box has no retrying `expect`: wait for it with `wait_for_function` (`scaled()` in `test_kiosk_thumbnails.py`). `server/ui/tests/test_browser_one_shot_reads.py` fails a `bounding_box()` with no `# one read:` comment beside it; it leaves `evaluate` to review, since about 30 asserted `evaluate` reads are one read on purpose and #240's carried the mark (#240 retro).
- A contrast or accessibility check starts from `assert_accessible(page)` (axe). A hand-rolled check covers only what axe reports as `incomplete`, and its docstring names that measurement: #247 hand-rolled about 60 lines of WCAG math beside axe, which caught the card regressions and left only text on the kiosk gradient (`bgGradient`) to a check of its own.
- An allowance that drops a browser error (`page_errors.allow`, a `requestfailed` filter) is as narrow as its cause: the frame, the URL and the tests where it happens. A test beside it raises the same error just outside it, such as from the page's own frame, and sees it still fail. #237's first `ABORTED_THUMBNAIL` dropped every `ERR_ABORTED` in two files, the main frame's included. A skip in a check tool, such as `kiosk_screens.py`'s animation rule, is as narrow: it sits in the one check the lead accepted it for, and a stand-in shows every other check still reporting the skipped case. #256 put OVERLAPS's animation skip in the shared `VISIBLE`, so ELLIPSIS missed a name cut in a glowing lane until review. A 404 is allowed only through `page_errors.allow_missing(url_pattern)`, since Chromium's 404 console error names no URL; `ui/tests/test_browser_missing_allowance.py` fails an `allow` that matches it (#206).
- A browser test that claims a step changes nothing records changes while the step runs (a MutationObserver, a call counter) and reads them once, and is checked by mutating every branch past the guard it covers, not only the one it names. #220's held-poll test missed a reload that undid itself before its retrying `expect` gave up; the review's mutation found it.
- A browser test's wall-clock bound, including a stand-in page's timer raced against a check or a recording's length, writes its slack as a formula in the docstring, gives at least the slack its neighbours give, and carries a should-pass mutation beside the should-fail ones: make the timer late by a bit less than the slack (`setTimeout(..., ms + 150)`) and see the test pass. A review finding or a reply that proposes a timing value goes through the same formula and mutation before it is sent, and a value that misses its stated goal goes to the lead before any long run. #236 held 300 ms, which left 300 ms of slack where the sibling test gives 1000; review then proposed 100 ms, which left 100 ms and failed with the timer 150 ms late. #239's tool test, a clip at 4 s against a 6 s recording, had neither until review. A test that drives a page by hand (`kioskNudge()`, a helper) where the page's own timer would do the same stretches that timer (`TEST_HOOKS` in `test_kiosk_slideshow.py`), and is mutated by removing the hand's call, which must fail it. #253's slideshow test raced the page's 10 s interval, and failed 4 of 4 with it at 5000 ms; four nudge tests in `test_kiosk_pages.py` (now racing, on deck, award, results by racer) pass with `kioskNudge()` running no content poll, since the page's own poll, every 0.5 or 1 s, comes inside `NUDGE_MS` (#253 retro).
- A change the diff makes to a page beyond the ticket's ask, such as a note that moves because a field was added beside it, is fixed in the diff, not listed under `## Still open`. #241's clip note moved under the new ICE servers field, and the fix was one template move.
- A CSS rule's test is mutated by removing the one declaration under test, and its data holds a case only that declaration decides, such as an unbreakable word for `overflow-wrap`. #250's mutations swapped wrap rules for an ellipsis, and removing `overflow-wrap` alone passed, since names with spaces wrap anyway. A fit or overflow check compares the element with its container's box, not with its own `scrollWidth`: in a centred flex column a nowrap name grows past its column. Look at the screenshots before the first mutation round: #250 found mid-word breaks in one after it, and ran the round again. Each condition of a filter is a branch: mutate each operand of an `&&` or `||` to `true` and to `false`, and replace a `min()`, `max()` or `clamp()` by each operand alone (#283's `min(1em, 2.85vw)` kept no mutant with `2.85vw` alone). `server/tools/operand_mutants.py` lists those mutants for each condition and call the diff adds, and the cases it reads past (a condition over several lines, a ternary) are listed by hand. #256's 32 mutations left `playState === 'running' && isFinite(endTime)` with none, and `a => true` passed. Write each near miss's should-fail twin first and see it fail, then the near miss: five of #256's near misses tested nothing until a mutation showed it. A mutation whose result differs from its expected one is explained in the mutation table in the round it runs, or its test or expectation changed: #272's t3 expected a failure, passed on a dead operand, and stood unexplained until review asked. A guard or hook is also mutated at its call site: delete the call and see a test fail. #282's collection guard took five mutations on its own lines and still passed with its call in `pytest_collection_modifyitems` deleted, until review.
- A browser test that measures text (a width, a line count, a fit) also passes with `DERBYNET_BROWSER_FONT="DejaVu Sans"` before the push, which draws `system-ui` as CI's Ubuntu does, where this machine draws Noto Sans (`server/README.md`). #256, #272 and #273 each held only on Noto, and #273 failed CI on "Heat 100" at 1280x800, which the variable reproduces.
- A condition that names a class of screens, such as TVs and projectors, is tested at its smallest common size too: 1024x768 for a projector. #250's photo cap was tested at 1920x1080 and 1280x800, and shrank a landscape photo at 1024x768 from 176 to 151.6 px.
- A poll that answers 204 signs everything it renders. `server/ui/tests/test_poll_signatures.py` changes each stored field in turn and fails a poll that still answers 204 when its rendering changed. #45's presenter signed the award's key and winner, not the names it shows.
